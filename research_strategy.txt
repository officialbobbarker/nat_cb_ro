INDIANA CHROMEBOOK ROLLOUTS — RESEARCH STRATEGY

PURPOSE
This file documents the methods used to identify when each Indiana public
school district adopted 1:1 student devices (Chromebooks, iPads, laptops),
so future iterations of this research can pick up where we left off and use
consistent sources/citations.

==============================================================================
WHAT WE'RE TRYING TO LEARN PER DISTRICT
==============================================================================
- year_started:    Calendar year the 1:1 program began (or upper bound)
- month_started:   Month of rollout if traceable (often back-to-school)
- one_to_one:      Yes/No/Partial — true 1:1 vs. classroom carts
- grade_levels:    Which grades got devices (often phased)
- device_type:     Chromebook / iPad / laptop / mixed
- notes:           Caveats, "upper bound" tag if we have only first-evidence
- source_url:      Primary source
- source_2:        Backup/secondary

NOTES CONVENTION
- "upper bound" = our earliest dated evidence; rollout may be earlier
- If FB shows a post mentioning a Chromebook handbook in Aug 2018, the
  upper bound is 2018 even though the actual rollout could be earlier
- Always prefer dated sources (newspaper articles > FB posts > tech pages)

==============================================================================
TIER 1 — INTENSIVE FACEBOOK METHOD (the main workhorse)
==============================================================================
Most Indiana districts have a very active Facebook page with chronological
posts that announce device rollouts, photo days, handbook updates, parent
nights, etc. Facebook's date stamps are the cleanest way to set an upper
bound year.

STEP A. FIND THE DISTRICT'S FACEBOOK PROFILE ID
1. Google: "<district name>" facebook
   OR navigate to the district's homepage and click their FB link in footer
2. Their FB URL will be one of:
   - facebook.com/<vanity-handle>            (e.g. /AdamsCentralCS)
   - facebook.com/profile.php?id=<numeric>   (numeric profile ID)
3. To get the numeric ID from a vanity handle, go to the page and look at
   the page source (Ctrl+U) and grep for "entity_id" or "page_id" — or
   simpler, click "About" and look at the URL path. Numeric IDs are 15
   digits, starting with 100xxxx... for personal-style pages.

STEP B. RUN MULTIPLE TARGETED SEARCHES ON THE PAGE
Facebook supports per-page search via this URL pattern:
   https://www.facebook.com/profile/<NUMERIC_ID>/search/?q=<TERM>
   (or)  https://www.facebook.com/<vanity>/search/?q=<TERM>

Run these queries on each district FB page. Specific device terms
(chromebooks, ipads, laptops) generally outperform generic ones
(device, AUP, 1:1) — Mike's experience. Priority order:

   1. chromebook            (singular)
   2. chromebooks           (plural — different result set!)
   3. ipad                  (singular, for Apple-shop districts)
   4. ipads                 (plural)
   5. laptop / laptops      (laptop-shop districts)
   6. tablet / tablets      (rare)
   7. macbook / macbooks    (Apple laptop districts)
   8. device / devices      (generic fallback when above empty)
   9. AUP / acceptable      (last resort)
  10. handbook / insurance  (rarely useful, last resort)

STOP early if you find a clear pre-2019 upper-bound post with
rollout-related content. The specific device terms usually surface
the rollout posts directly, so don't burn calls on generic terms
unless device-specific ones come up empty.

CRITICAL: FB search is NOT stem-aware. Searching "chromebook"
returns DIFFERENT posts than "chromebooks". Always run BOTH forms.
(Mike caught this for South Harrison: chromebook singular gave 1
hit (2021-08-24); chromebooks plural surfaced a 2017-05-01 post
announcing chromebooks for 2017-18 SY — 4 year difference.)

EFFICIENCY: For each district, FB usually returns at most ~5-15
posts per search term. Most are duplicates across terms. After 3-4
terms with no new dates, additional searches rarely help. If
chromebook + chromebooks + device returned a clear pre-2019
device-rollout post, you can stop.

CRITICAL: FB search is NOT stem-aware. Searching "chromebook"
returns DIFFERENT posts than "chromebooks". Mike caught this for
South Harrison: "chromebook" singular returned only 1 result
(2021-08-24); "chromebooks" plural surfaced an additional post from
2017-05-01 announcing "chromebooks will be provided beginning with
the 2017-18 school year". A 4-year difference. Always run both forms.

IMPORTANT: FB's term search DOES match the post body AND the link
card title/description. But FB's relevance ranking can suppress older
results for some terms while surfacing them for synonyms. So always
run multiple related terms even when one matches "should" cover the
others.

Example: Vincennes Community SC had only 2 chromebook results visible
(both 2025), but searching "AUP" surfaced a 2018-07-13 post sharing
the "LHS Chromebook AUP 2018-19" page. The 2018 post DID contain the
word "chromebook" in both the body and the link card description, but
FB's chromebook-search ranking didn't surface it. Searching "AUP" did.
That moved the upper bound from 2025 to 2018 — 7 years earlier.

Lesson: never trust a single-term search to be exhaustive. Run
chromebook AND AUP AND acceptable AND device AND handbook etc.

DO NOT use "1:1" as a search term — FB matches it to substrings like
"11/19" (dates), "1:11" (times), "11:11", "1 1" etc. Almost every
result is a false positive (school closure dates, time stamps,
basketball scores). It's not worth filtering manually.

Sort results by oldest if possible — the EARLIEST dated post is what
sets the upper-bound year.

IMPORTANT: When FB results are unsorted, the oldest post is NOT
necessarily at the bottom. It may appear in the middle of the list.
Skim the date stamp of EVERY result before deciding which is earliest.
Don't trust position alone.

Note: FB's rendered date text is visually scrambled (anti-scrape
character interleaving via absolute-positioned spans), so visible text
is unreliable. INSTEAD, the underlying page HTML contains a JSON blob
with a `creation_time` field (Unix epoch) for each visible post.

CONCRETE METHOD (Chrome DevTools / javascript_tool):

The `creation_time` regex approach is INCOMPLETE — it only extracts
JSON timestamps for the top ~2 most-recent posts. Older posts have
their dates rendered as scrambled CSS-positioned char spans without
JSON metadata.

The reliable method is to DECODE THE CSS-POSITIONED DATE SPANS:
- Each visible date is rendered as a flex container of single-char
  <span> elements
- Real chars use `position: relative` and have CSS `order` integers
  that determine visual layout
- Decoy chars use `position: absolute` (anti-scrape noise)
- To reconstruct: filter to position:relative chars, sort by `order`,
  concatenate

JS to extract all visible decoded dates from a search results page:

```javascript
function collectDates() {
  const out = new Set();
  document.querySelectorAll('span').forEach(s => {
    if (s.textContent.length !== 1) return;
    if (!/[A-Za-z0-9, ]/.test(s.textContent)) return;
    // Group will be processed via parent
  });
  // Group char-spans by parent
  const groupsMap = new Map();
  document.querySelectorAll('span').forEach(s => {
    if (s.textContent.length !== 1) return;
    if (!/[A-Za-z0-9, ]/.test(s.textContent)) return;
    const p = s.parentElement;
    if (!groupsMap.has(p)) groupsMap.set(p, []);
    const cs = window.getComputedStyle(s);
    groupsMap.get(p).push({
      char: s.textContent,
      order: parseInt(cs.order) || 0,
      position: cs.position
    });
  });
  for (const [, chars] of groupsMap) {
    const rel = chars.filter(c => c.position === 'relative')
                     .sort((a,b) => a.order - b.order);
    const s = rel.map(c => c.char).join('');
    if (/(?:January|February|March|April|May|June|July|August|September|October|November|December)\d{1,2},20\d{2}/.test(s))
      out.add(s);
  }
  return out;
}
```

Run collectDates() repeatedly while scrolling — FB lazy-renders date
spans for posts as they enter the viewport, so you must scroll
through ALL post positions to capture all dates.

ADDITIONALLY check `document.body.innerText` for plain-text dates:
some older posts (especially pre-2018) render dates as plain text
"July 20, 2016" instead of the scrambled-span format. Match with
   /(?:January|February|...|December)\s+\d{1,2},?\s*20\d{2}/g
on the visible text, and merge those dates into your set.

The OLDEST date returned (or earliest after parsing to ISO date) is
the upper-bound year for the rollout.

ALL CAVEATS (still apply):
1. Run multiple search terms (chromebook, ipad, laptop, AUP,
   acceptable, device, handbook, insurance, rollout) — FB ranking
   surfaces different posts for different terms
2. Skip "1:1" — too many false positives from "11/19" date matches
3. Scroll incrementally (e.g. 400px steps with 1.2s waits) to load
   all lazy-rendered posts
4. The CSS-order decoder may still miss a few posts if scrolling
   doesn't trigger their date span rendering — accept the oldest
   you find as a reasonable upper bound

CRITICAL — INTERPRETING POST CONTENT:

PROJECT GOAL: Find the first year students in a district were using
1:1 (or near-1:1) devices for regular learning activities. This
includes BOTH school-issued AND student-owned (BYOD) devices used
for learning. The hypothesis is that the shift from pen-and-paper to
personal device use during class is an important inflection point in
education strategy, and we want to capture WHEN it happened.

A search hit for "device" or "chromebook" doesn't always mean the
post is about regular learning device use. False positives include:
- Auction listings or fundraiser device giveaways (e.g. "raffle a
  Chromebook" — not classroom use)
- Generic instructions to "use your device" for one-off online forms
- Tech department job postings
- "Device-free" assemblies or pledges
- Sports-context mentions

TRUE positives that count for our research:
- Distribution/pickup of student devices
- 1:1 initiative announcements
- BYOD program announcements (these DO count — student-owned devices
  used for class is exactly the shift we're tracking)
- Acceptable Use Policy or Device Insurance for student devices
- Chromebook/iPad/laptop return / collection from students
- Specific grade-level rollouts
- Board approvals of "1:1 device" purchases or BYOD policies

ALWAYS read the visible post body before treating a date as the
upper bound. If the oldest date's content is unrelated, MOVE TO THE
NEXT-OLDEST date that has rollout-related content.

If the oldest date's content is unrelated, MOVE TO THE NEXT-OLDEST
date that has rollout-related content. (Mike caught this in
Greenfield-Central — June 3, 2019 device post was unrelated; the
real upper bound is December 16, 2019 which mentions school-
provided devices.)

When in doubt, flag the post and confirm with Mike rather than guess.

CRITICAL: FB search results lazy-load — only ~3-7 posts are in the DOM
at first, and more load only as you scroll. The `creation_time` regex
will MISS older posts that haven't been rendered yet. To get the true
oldest, you MUST:

  1. Scroll to bottom (window.scrollTo(0, document.body.scrollHeight))
  2. Wait ~1-2s for new posts to load via XHR
  3. Repeat until scrollHeight stops growing (or until "End of Results"
     marker appears)
  4. ONLY THEN extract creation_time and take min

Skipping the scroll step gives the OLDEST-VISIBLE-AT-FIRST date, not
the OLDEST date. This can produce wrong upper bounds — e.g., if FB
initially shows 2020 posts but a 2018 post exists deeper in results,
you'll incorrectly tag the rollout as 2020.

Also: try multiple search terms. "chromebook" may show only recent
COVID-era posts, while "1:1" or "device" may surface older 1:1
initiative announcements that predate the chromebook search hits.

STEP C. ALSO CHECK SUB-PAGES
Many districts have separate FB pages for:
- The high school    (often the first to get devices)
- The middle/jr-high school
- The district tech department
Search each sub-page with the same query list. The HS page frequently
has the earliest device posts because phased rollouts started in HS.

STEP D. WHAT TO RECORD
For each match:
- The post date (this becomes year_started, with "upper bound" caveat)
- A 1-line quote of what the post said about the device
- The FB profile URL with the search query (for source_url)
- If the district has multiple matching posts, prefer the OLDEST one
  that clearly references device rollout/distribution

Example source_url:
  https://www.facebook.com/profile/100063543403755/search/?q=chromebooks

==============================================================================
TIER 2 — DISTRICT WEBSITE + WEB ARCHIVE METHOD
==============================================================================
When FB is sparse or the district doesn't post much, fall back to:

A. DISTRICT TECHNOLOGY PAGE
   Most districts have a "/technology" or "/departments/technology" page
   with a Chromebook handbook PDF. The PDF often has a year in the title
   or filename (e.g. "2019-20-Chromebook-Handbook.pdf"). That year is the
   upper bound.

B. WAYBACK MACHINE (web.archive.org)
   For "<district domain>/technology" page:
   https://web.archive.org/web/*/<district-domain>/technology
   Look for the EARLIEST snapshot that mentions Chromebooks/devices/1:1.
   That snapshot date is the upper bound.

   Particularly useful query patterns on Wayback:
   - First snapshot mentioning "Chromebook" anywhere on district site
   - First snapshot of a 1:1 / take-home agreement form
   - Earliest version of the technology handbook

C. SCHOOL BOARD MINUTES / AGENDAS
   Many Indiana districts post board minutes (PDF). Search the district
   site for "chromebook" or "1:1". Board approvals to purchase devices
   are very precisely dated. Often listed as a financial item.

TIER 4 — LAST RESORT
==============================================================================
A. Search for the district's hiring of a Tech Director / Coordinator —
   often coincides with device rollout.
B. Search "<district name> Title IV-A funds" or "Innovation Grant" —
   Indiana awarded Classroom Innovation Grants in 2012 that funded early
   1:1 programs (Richmond won one).
C. LinkedIn — district tech directors often list "Led 1:1 rollout in
   YYYY" on their profile.
D. If absolutely no public evidence exists, leave the row blank rather
   than guess. Better to have a NULL than a wrong year.

==============================================================================
DATA HYGIENE RULES
==============================================================================
1. NEVER overwrite a row that already has data — only fill empty rows
2. ALWAYS keep the .bak.csv in sync (one snapshot per session start)
3. Use the EXACT district name from the existing CSV (matches NCES file)
4. Years should be 4-digit integers; "2020 (by)" notation for upper bounds
   that cannot be pinned more precisely
5. Quote the source URL exactly — don't paraphrase or shorten
6. For "Yes" in one_to_one, require explicit evidence of a take-home or
   per-student device — "classroom cart" only = leave blank or "Partial"
7. Never invent a numerical year just to fill the cell
